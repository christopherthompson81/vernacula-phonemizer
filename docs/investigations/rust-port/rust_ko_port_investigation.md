# Rust port: Korean (ko)

The ko engine (#1463): `src/languages/korean/{korean,g2p,manifest,normalize,numbers}.ts`
→ `rust/vernacula-phonemizer/src/languages/korean/*.rs`. The import closure outside the directory is
`core/{normalizeSymbols (makeSymbolNormalizer), clauses, provenance, loadTsv, loadManifest, numbers (digitIndex)}`,
all already ported, so no new core module is needed.

Foreign runs: embedded Latin goes to the registry's default foreign reader (English). `scripts.ts` overrides
`ko: { Han: "ko" }`, so Han inside Korean text routes to the host itself, which `readForeignRun` declines
(target equal to host would recurse) and the run falls to the default reader. No neural entry
(`neuralRegistry.ts` does not list `ko`). No Roman policy.

## Run 5 — 2026-10-10 10:35 (TS findings from reading, checked against Node)

**Question.** Do the defects seen while reading the TS actually show in its output?

**Command.** `npx tsx .probe/ko/defects.mts` (normalizeKorean and phonemize on each candidate) and
`npx tsx .probe/ko/tens_reach.mts` (how often tensification.tsv's whole-word key reaches a Hangul run of
normalized FLEURS ko_kr column 3).

**Raw finding.** (Rust reproduces every one of these byte for byte; none is fixed here.)
1. **°F keeps the guard the °C rule was fixed away from.** normalize.ts's header comment explains that
   `(?![\p{L}])` rejected the particle a Korean temperature is normally followed by, and moved °C to
   `(?![\p{sc=Latn}\p{M}])`. The °F rule still has `(?![\p{L}\p{M}])`: `70°F 정도` → `화씨 칠십도 정도`, but
   `70°F에서` → `칠십도에프에서` (scale name lost, F spelled as the letter 에프 by rule 9). Reached by no
   FLEURS line (Run 4: °F is probe-only).
2. **A decimal whose integer part is past 2^53 deletes it.** Rule 6 composes `numberToWords(Number(int))`,
   which is `""` there, so `99999999999999999999.5` → `점오` and `12345678901234567890.25배` → `점이오배`. The
   same `""`-contract hole korean.ts already closed for a bare digit run (its `spellDigits` fallback), still
   open in rule 6.
3. **A relational operand stops before a glued counter or particle and strands it after the predicate.**
   `OPERAND` is `\d+|[가-힣]+|[A-Za-z]`, so in `값=3원` the right operand is `3` and the 원 is left after 같다:
   `값은 삼과 같다원`; `x=3개` → `엑스는 삼과 같다개`.
4. **A one-letter Latin operand is taken out of the middle of a word.** `[A-Za-z]` has no letter guard, so
   `xy = z` → `x와이는 제트와 같다` (the y of xy becomes the topic, the x is left as Latin) and `ab < c` →
   `a비는 씨보다 작다`. The comment says a longer Latin word "leaves the sign dropped, as before".
5. **The lexical-tensification list is keyed on the whole run, and the run carries its particle.** korean.ts's
   TOKEN is `[가-힣]+`, so `가능성` is tensed (`kɐnˈɯŋs͈ɘŋ`) while `가능성이` / `가능성은` are not
   (`…sɘŋi`, `…sɘŋɯn`). Over FLEURS ko_kr: 42,431 runs, 307 an exact key, 733 more that START with a key of
   ≥2 syllables followed by more Hangul. ⚠ That second count is a prefix heuristic, not a parse: its first
   twelve are `일상+생활을 골프+는 골프+는 도살장+에 요건+들은 시스템+을 필수적+인 절대+적인 서비스+는 실제+로는
   칠십+육점을 달성+했습니다`, so it includes compounds and derivations where the key's indices may or may not
   carry over. It bounds the reach question; it does not count real losses.
6. Cosmetic: g2p.ts's header docstring keeps a drafting note, `국물→kuŋmuɭ… wait kuŋmul`.

**Implication.** Report all six in the PR; fix none in Rust (Rust reproduces the TS). 1–4 are each a
one-rule TS fix with a pinning test; 5 is a design question (stem lookup vs particle stripping) that needs
measuring before it is changed.
