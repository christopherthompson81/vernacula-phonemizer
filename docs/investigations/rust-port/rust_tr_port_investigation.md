## Run 5 — 2026-10-10 20:47 (reading for correctness: TS findings)

**Command.** `npx tsx .probe/tr/findings.mts` — the TS engine's own normalize / phonemize / numberToWords output on
synthetic inputs chosen while reading each file against its docstring. Rust reproduces every one (they are now in
probes/tr.txt); none is fixed here.

**Raw finding.**
1. **numberToWords drops the scale word from 10¹⁸ up** (numbers.ts). `SCALES` stops at katrilyon (10¹⁵), so
   `SCALES[6]` is `undefined`, which `join` writes as "": `numberToWords(1e18)` = `"bir "`, `1e21` = `"bir "`,
   `2.005e21` = `"iki  beş "`. End to end, `1000000000000000000000` reads *bˈiɾ* (“one”) and
   `2005000000000000000000 kişi` *icˈi bˈeʃ ciʃˈi* — a confidently wrong number, not a digit fallback. Rare (a
   19+-digit integer), but silent.
2. **The circumflex fold erases the palatalization it marks** (g2p.ts `trLower`). In Turkish orthography â/û after
   k/g/l mark a PALATAL consonant (kâr vs kar, lâle, kâğıt, rüzgâr), but the fold runs BEFORE the scan, so the scan
   sees a back vowel: `kâr` = `kar` = *kˈaɾ*, `lâle` *ɫˈale* (dark l), `rüzgâr` *ɾyzɡˈaɾ*, `hikâye` *hikajˈe*. The
   scan already has the palatal outputs (c, ɟ, clear l) but keys them only on a FRONT vowel, and by the time it runs
   the circumflex that would say "palatal here" is gone. A linguistic finding to MEASURE (the referee may or may not mark it), not a fix.
3. **The pre-accenting tail fires on plain nouns ending -mA/-sA/-lA** (turkish.ts `PRE_ACCENT_RE`), which is
   anchored only at the word END, not at a morpheme boundary: `elma` → *ˈelma*, `masa` → *mˈasa*, `kele` → *cˈele*
   (none of the three is in stress.tsv; `hala`/`kasa` are, so they are lexicon readings). Whether this is net
   positive is a measurement question — the header records that the bare -sIn was excluded for exactly this cost —
   so it is reported, not judged.
4. **attachSuffix's dört→dörd test is case-sensitive while the tokenizer is not**: TOKEN's suffix class carries
   `iu`, so `34'Ü` reaches `attachSuffix` with `Ü`, the lower-case-only VOWEL test misses, and it reads *døɾtˈy*
   where `34'ü` reads *døɾdˈy*. Conversely capital `İ` has no simple case fold to `i`, so the class REJECTS it:
   `1985'İN` reads *… bˈeʃ ˈin* (the suffix split off as its own word) where `1985'in` reads *beʃˈin*. All-caps text
   only.
5. **A sentence-final number before the next sentence is claimed as an ordinal** (turkish.ts TOKEN's `N.` branch):
   `Yıl 2004. Sonra geldi.` reads *… icˈi bˈin døɾdynd͡ʒˈy sonɾˈa …* — "two thousand fourth", and the phrase break is
   lost. The header's corpus count found only the end-of-input case; a mid-text one has no licenser test to decline it.
6. **The dot-form clock has no context** (normalize.ts step 3): `fiyat 1.50 lira` → `fiyat 1 50 lira`, `sürüm 2.15`
   → `2 15`. Turkish writes decimals with a comma, so a dot-decimal is foreign-style input; low priority.
7. Latent: a ğ after a CONSONANT lengthens the consonant (`rğa` → *ɾːˈa*, `lğı` → *lːˈɯ*) because `segs[last]` is
   whatever came last; and a fractional stress.tsv value would index `nuclei[syl - 1]` as undefined and drop the mark
   entirely (no row is fractional; the Rust reproduces it with a `fract() == 0` guard). Neither is reachable from
   real words today.
8. No `Object.prototype` read is reachable: VOWEL_IPA/CONS_IPA/circumflexFold get one code point, letterNames one
   lowercased code point, DOTTED_ABBREV a fold of its own keys (miss handled), CLAUSE_MARK one of its own keys, HIGH a
   VOWEL letter.

**Implication.** Reported in the PR, not fixed (the bidirectional rule: TS first, in a separate change).
test/turkish.test.ts's 51 `toBe` and 2 `toContain` pins are now a Rust test (`.probe/tr/pins.mjs` extracts them
mechanically; no reading typed by hand).
